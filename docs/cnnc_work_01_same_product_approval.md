# 中核商城新增监控商品同款审批处理和价格指数同步

> 适用频率：每日工作，原则上日清。  
> 适用对象：中核商城每日新增/推送到“价格监测检验中、同款审批、监控预警/标准商品价格库”的监控商品。  
> 目标结果：完成同款审批、生成价格指数，并将结果同步回中核商城，使商城侧状态由“校验中”变为“校验成功”或在确无两条有效同款时变为“校验失败”。

## 1. 业务边界

### 1.1 需要处理的内容

- 新增监控商品的同款采集结果审批。
- 参考链接同款、互联网召回同款的人工复核。
- 有效同款达到要求后的价格指数生成与推送。
- 同款匹配中、采集未返回、同款不足等异常状态判断。

### 1.2 不需要处理的内容

- 中核商城中“冻结”状态商品通常由商城侧维护，不主动处理。
- 商品状态只是查看项时，不在商城侧直接改状态。
- 同款数据还在“同款匹配中”时，不要直接推送。

## 2. 系统入口与页面

| 系统 | 页面/菜单 | 用途 |
|---|---|---|
| 中核商城 | 电子商城 → 商品管理 → 标准商品管理 → 标准商品价格库 | 查看标准商品、价格指数、同款信息、校验状态 |

## 3. 核心判定规则

| 规则项 | 通过标准 | 驳回/暂缓标准 |
|---|---|---|
| 同款数量 | 至少 **2条有效同款** | 0条或1条有效同款，判定为同款不足 |
| 商城数量 | 2条有效同款需来自 **不同商城/不同商城编码** | 同一商城多条链接不能同时作为最终两条同款 |
| 商品状态 | 链接可访问、商品上架、价格可核对 | 链接失效、下架、页面打不开，驳回或解绑 |
| 型号/规格 | 型号、规格、关键参数一致 | 型号后缀、功率、容量、尺寸等关键参数不一致，驳回 |
| 价格 | 与参考价或当前价格指数差异不要过大；优先选择较低且合理的同款价 | 高于参考价/价格指数约30%以上，需谨慎；明显异常价驳回、解绑或重采 |
| 参考链接 | 客户/商城侧提供的参考链接通常优先认为可信，但仍需人工核对 | 参考链接本身错款、价差异常、链接失效，不能直接通过 |

## 4. 日常操作流程

### Step 1：查看中核商城新增监控商品状态

1. 登录中核商城。
2. 进入“标准商品价格库”或对应的价格监测检验列表。
3. 重点查看当天新增的“校验中/待校验/价格监测检验中”数据。
4. 记录需要处理的商品编码、商品名称、当前状态。

状态理解：

- **已生效**：商城正常可采购的商品，价格指数更新主要影响这类商品。
- **冻结**：商城侧维护状态，通常不用处理。
- **解冻中**：商城侧可能等待我们修复价格/同款问题，修复后商城侧再改回已生效。
- **校验中**：我们推送前或流程处理中。
- **校验成功**：已生成并推送成功。
- **校验失败**：没有满足两条以上不同商城同款，或主动推送失败结果。

### Step 2：进入SaaS同款审批页面

1. 进入 SaaS 价格监测运营平台。
2. 打开同款审批相关菜单。
3. 租户/客户选择中核相关租户。
4. 查看待审批、已审批、同款匹配中等状态。
5. 优先处理当天新增且流程已返回同款结果的数据。

同款来源一般分两类：

- **参考链接**：中核商城或供应商推送时带过来的参考链接。一般默认可信，但仍要核验。
- **互联网**：SaaS根据品牌、名称、型号等自动采集、召回、模型校验后返回的同款。

### Step 3：逐条核验同款

对每条候选同款执行以下核验：

1. 打开候选链接。
2. 看商品是否上架、页面是否有效。
3. 比对品牌、型号、规格、容量、功率、尺寸、颜色等关键属性。
4. 核对页面价格与SaaS返回价格是否一致或接近。
5. 判断是否与监控商品为同款。

处理动作：

- 确认为同款：审批通过。
- 明显非同款：驳回。
- 链接失效/下架：驳回。
- 页面价格与系统价格明显不一致：先驳回；确需使用时，需人工修正价格后再通过。
- 型号不一致：原则上驳回，不因名称相似而通过。

### Step 4：判断是否满足价格指数生成条件

通过审批后，检查最终有效同款是否满足：

1. 有效同款数 ≥ 2。
2. 有效同款来自不同商城。
3. 价格没有明显高溢价异常。
4. 不是同一商城一物多码重复链接。

满足条件后，系统会生成价格指数；不满足时不得强行推送成功。

### Step 5：查看价格指数与同款明细

1. 进入价格指数/监控预警相关页面。
2. 选择中核相关客户/租户。
3. 查询当前监控商品。
4. 打开同款明细。
5. 查看价格指数、参考价、最高价、最低价、同款商城分布。

检查重点：

- 价格指数是否明显偏高。
- 同款是否来自不同商城。
- 是否存在同一商城多个链接被同时保留。
- 是否存在高于参考价约30%以上的异常同款。

### Step 6：推送价格指数

1. 价格和同款确认无误后，点击“立即推送”或使用批量推送工具。
2. 推送完成后回到中核商城查看状态。
3. 正常结果：商城侧由“校验中”变为“校验成功”。
4. 若确实没有两条以上有效同款，推送后可能变为“校验失败”。

> 注意：如果商品仍处于“同款匹配中”，或同款审批页面没有返回任何数据，不要直接点击推送。直接推送容易把本可等待返回的数据推成“校验失败”。

## 5. 批量处理建议

当当天数据量较大时，可使用批量工具：

1. 先执行计算。
2. 再查询待推送数据。
3. 抽样或逐条查看同款与价差。
4. 确认无异常后批量推送。

批量前必须先排除：

- 同款匹配中未返回的数据。
- 只有一条同款的数据。
- 链接失效的数据。
- 价格明显异常的数据。
- 同一商城重复保留的数据。

## 6. 异常处理规则

| 异常场景 | 判断方法 | 处理动作 |
|---|---|---|
| 同款匹配中 | 同款审批页无返回数据，状态仍在匹配 | 等待；正常当天应返回，次日仍未返回再排查流程阻塞 |
| 参考链接仅1条 | 客户只提供1条，互联网也未召回有效同款 | 可推送失败；后续等客户/供应商补链 |
| 客户提供2条但系统只采到1条 | 采集失败或某商城采不到 | 手动补采或导入客户提供链接，不能直接推失败 |
| 互联网召回错款 | 型号/规格不一致 | 驳回该同款 |
| 链接下架 | 页面打不开或显示下架 | 驳回或解绑 |
| 价格偏高 | 高于参考价/价格指数约30%以上 | 优先剔除、解绑或重新采集低价同款 |
| 同一商城多条 | 商城编码相同 | 只保留其中一条有效低价/合理链接 |

## 7. 交付检查清单

- [ ] 当天新增数据已查看。
- [ ] 同款审批已完成。
- [ ] 每个成功推送商品至少保留2条不同商城有效同款。
- [ ] 链接均可访问且上架。
- [ ] 型号、规格、关键属性一致。
- [ ] 价格未出现明显高溢价。
- [ ] 中核商城状态已更新为“校验成功”或合理的“校验失败”。
- [ ] 异常数据已记录，便于后续反馈或工单追踪。
