# 中核核心工作事项 01：新增监控商品同款审批处理和价格指数同步

> 适用范围：中核商城标准商品价格库 / SARS 同款审批 / 新增监控商品每日处理  
> 工作频率：每日工作，一般日清  
> 处理目标：对中核商城新增监控商品完成同款审批、价格指数计算和同步推送  
> Agent 定位：提供流程指引、规则判断、排查建议；不得自动审批、自动解绑、自动推送、自动改库。

---

## 1. 工作事项定义

本事项对应中核 8 项核心工作中的第 1 项：

**中核商城新增监控商品同款审批处理和价格指数同步。**

每日中核商城会推送新增监控商品，这些商品会进入同款采集和审批链路。运维侧需要检查同款数据是否有效、链接是否可访问、价格是否合理，并在满足条件后推动价格指数生成和同步。

---

## 2. 入口系统与核心菜单

### 2.1 中核商城侧

进入：

```text
电子商城 / 商品管理 / 标准商品管理 / 标准商品价格库
```

标准商品价格库中可查看：

- 标准商品信息；
- 价格指数信息；
- 同款信息；
- 价格指数推送历史；
- 当前最新价格指数数据；
- 商品状态。

### 2.2 SARS / 同款审批侧

新增监控商品的同款数据在 SARS 侧处理。中核对应菜单通常选择：

```text
CNC / 中核 / 同款审批 / 监测审核
```

审批数据来源包括：

1. **参考链接**：客户推送商品时自带的参考链接；
2. **互联网采集**：系统根据品牌、名称、型号等组合，从外部商城采集、召回并经过两轮模型校验后返回的数据。

---

## 3. 商品状态认知

| 状态 | 含义 | 是否重点处理 |
|---|---|---|
| 已生效 | 商城正常可采购、可下单的标准商品 | 是，日常更新主要关注 |
| 冻结 | 商城侧自行维护，通常表示暂不使用或下架 | 否，通常无需处理 |
| 解冻中 | 供应商/商城侧核查后等待重新上架 | 一般只查看，不主动干预 |
| 校验中 / 同款匹配中 | 新增监控商品仍在同款采集、召回或审批流程中 | 需要等待或排查 |
| 校验成功 | 同款满足要求并生成价格指数后，商城状态自动变更 | 正常完成 |
| 校验失败 | 无法生成价格指数，例如无同款或只有一条同款 | 失败态，后续可能由班车补同款 |

---

## 4. 每日处理节奏

### 4.1 白天处理重点

白天主要做：

1. 查看新增商品的同款审批数据是否回流；
2. 审核参考链接和互联网采集同款；
3. 检查链接有效性；
4. 检查同款是否真实匹配；
5. 检查采集价格与页面价格是否一致；
6. 检查同款价差是否过大。

### 4.2 推送时间建议

正常情况下，建议**18:00 后再统一推送当天数据**。

原因：

- 中核侧通常下午 6 点前会结束当天审核或推送；
- 白天数据可能还在采集、匹配、回流；
- 过早推送可能将“仍在同款匹配中”的商品推成校验失败。

如客户明确要求加急，可优先处理指定商品。

---

## 5. 标准处理流程

### Step 1：查看新增监控商品

进入同款审批/监测审核菜单，查看当天新增商品状态。

重点查看：

- 是否已有审批数据；
- 同款类型是参考链接还是互联网采集；
- 是否仍处于同款匹配中；
- 是否有 2 条及以上不同商城的有效同款。

### Step 2：区分参考链接和互联网采集

| 类型 | 来源 | 处理方式 |
|---|---|---|
| 参考链接 | 客户随商品推送提供 | 一般默认可信，但仍需核验链接、价格、同款关系 |
| 互联网采集 | 系统自动采集外部商城 | 必须人工复核是否同款、链接是否有效、价格是否一致 |

注意：

- 客户提供的参考链接通常认为是同款，但不能跳过系统流程；
- 互联网采集数据经过模型校验，但仍可能存在误召回、链接失效、价格不一致。

### Step 3：审核同款是否真实一致

审批时应核验：

- 商品品牌是否一致；
- 商品型号/规格是否一致；
- 图片和标题是否能够支持同款判断；
- 单位、容量、功率、电压、材质等关键规格是否一致；
- 是否存在看似相似但实质不同的商品。

判断不确定时，应人工打开链接核查。

### Step 4：检查链接是否有效

以下情况应驳回：

- 链接打不开；
- 商品已下架；
- 链接跳转到无关商品；
- 页面商品与采集标题/图片不一致；
- 采集价格与页面实际价格明显不一致。

### Step 5：检查价格合理性

同款价格应与参考价或标准商品价格接近。

经验规则：

- 价差尽量控制在 **30% 以内**；
- 若参考价约 799，则匹配价格不宜超过 1000，也不应远低于参考价；
- 价格差异过大时，应优先怀疑错误链接、离群值、历史价格未更新或非同款。

### Step 6：审批通过或驳回

| 情况 | 处理 |
|---|---|
| 同款真实一致、链接有效、价格合理 | 审批通过 |
| 非同款 | 驳回 |
| 链接失效/下架 | 驳回 |
| 页面价与采集价不一致 | 驳回 |
| 价格差异过大且无法解释 | 驳回或反馈客户确认 |
| 只有一条有效同款 | 不满足指数生成条件，应按失败流程处理 |

### Step 7：生成价格指数

中核价格指数生成条件：

```text
至少 2 条及以上不同商城的有效同款数据
```

注意：

- 同一个商城多个重复链接不能重复计入；
- 一物多码场景下，系统会做去重/去极值；
- 客户倾向尽可能保留较低合理价格；
- 若系统去极值后保留高价、剔除低价，需要重点关注，可能属于异常。

### Step 8：推送价格指数

确认价格指数生成后，点击“立即推送”。

推送后商城侧状态会自动变更：

| 推送结果 | 商城侧状态 |
|---|---|
| 有 2 条及以上有效同款，价格指数生成成功 | 校验成功 |
| 无同款或只有 1 条有效同款，无法生成指数 | 校验失败 |
| 同款仍未回流或仍在匹配中 | 不应直接推送，应等待或排查 |

## 6. 异常情况处理规则

### 6.1 同款匹配中 / 无审批数据

表现：

- 审批页没有数据；
- 状态仍为“同款匹配中”；
- 当天新增商品没有返回同款。

处理：

1. 不要直接点“立即推送”；
2. 等待爬虫和模型返回同款审批数据；
3. 若次日仍未返回，需排查采集/召回/爬虫环节是否阻塞；
4. 如果系统流程阻塞，应记录问题并反馈相关开发或爬虫同事。

风险：

```text
若在无审批数据时直接推送，可能导致商品进入校验失败。
```

### 6.2 只有一条同款

表现：

- 只有参考链接一条；
- 或互联网采集只返回一条有效同款；
- 无法满足“2 条不同商城同款”条件。

处理：

1. 确认是否确实只有 1 条有效同款；
2. 如无其他有效同款，可按校验失败流程处理；
3. 对只有一条同款的监控商品，可解绑同款后推送，使其进入校验失败；
4. 后续若客户或供应商需要上架，会通过班车数据提供新增同款。

注意：

- 解绑和推送是人工操作；
- Agent 不得自动解绑、自动推送。

### 6.3 客户提供了两条不同商城链接，但系统只采到一条

处理：

1. 不应直接推送校验失败；
2. 如果客户提供的两条链接均有效、且为不同商城、且确认为同款，可以将客户提供链接作为同款补入系统；
3. 重新计算价格指数；
4. 再进行推送。

### 6.4 客户提供链接价差过大

例如：

```text
一条 10 元，一条 20 元，价差接近一倍。
```

处理：

1. 不建议直接推送；
2. 应反馈客户或商城侧重新确认；
3. 等客户重新处理或确认后再推进；
4. 避免因离群价格导致价格指数异常。

### 6.5 一条正确、一条错误

处理：

1. 正确链接可保留；
2. 错误链接不参与价格指数计算；
3. 若剩余有效链接不足 2 条，则无法生成价格指数；
4. 可等待补充同款或走失败流程。

---

## 7. 批量处理建议

每日数据量可能较大，例如百条以上。

处理建议：

1. 优先通过批量工具查询 Document ID 和商品信息；
2. 批量查看同款审批状态；
3. 对风险较低、同款明显正确、价差合理的数据批量通过；
4. 对价差大、链接异常、模型疑似误判的数据逐条人工核查；
5. 当 SARS 平台无法批量操作时，可使用内部小工具辅助处理。

注意：

- 批量处理前必须保证数据质量；
- 不要为了速度跳过链接有效性和价格一致性检查；
- 客户商城侧会复核，质量差会导致返工。

## 9. Agent 禁止自动执行的操作

Agent 只能提供诊断和建议，不得自动执行：

- 自动审批通过；
- 自动驳回；
- 自动解绑同款；
- 自动点击立即推送；
- 自动重算价格指数；
- 自动修改价格指数；
- 自动写库；
- 自动删除数据；
- 自动重推任务。

涉及以上动作时，只能输出：

```text
建议人工在系统中核查后处理。
```
