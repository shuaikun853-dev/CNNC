# 第二步可推送价格校验设计

## 目标

修正第二步监控状态表的可推送判定，避免采集和同款状态看似成功、但实际没有有效推送价格的数据被误判为可推送。

## 判定顺序

每条 SaaS 监控记录按以下顺序判断：

1. `isSync != 1`：不能推送，沿用“采集未成功”分类。
2. `isSyncStandard != 1`：不能推送，沿用现有同款匹配分类。
3. `syncPriceStatus == 5`：不能推送，分类为“价格检测校验失败”。
4. `syncPriceStatus != 5`：继续校验 `newPrice`。
5. `newPrice` 必须是可解析且大于 `0` 的数值。`null`、空字符串、非数字、`0` 和负数均不能推送，分类为“推送价格为空或无效”。
6. 前述校验全部通过后，才标记 `是否可推送=是`。

`syncPriceStatus` 不被忽略；方案采用“状态值 `5` 先拦截，其余状态再校验有效推送价格”的两步价格校验。

## 输出

- 状态 Excel 增加 `newPrice` 列，保留接口原始值供人工核验。
- `可推送数据` 只包含通过全部新规则的记录。
- `需处理数据` 包含价格检测校验失败和推送价格为空或无效的记录。
- `状态统计` 按新的最终分类重新统计。

## 实现边界

- 修改固定入口 `scripts/export_current_monitor_status.py` 的状态判定，不改变中核和 SaaS 的分页、认证、合并及只读边界。
- 不调用审批、推送、保存、提交、招商局、爬虫或数据库 SQL。
- 同步更新 `AGENTS.md` 与 `TESTING.md` 中第二步的可推送规则。

## 测试

采用测试优先实现，至少覆盖：

- 两个状态成功、`syncPriceStatus != 5`、`newPrice` 为正数或正数字符串：可推送。
- `syncPriceStatus == 5` 且 `newPrice` 有值：仍不能推送。
- `newPrice` 为 `null`、空字符串、非数字、`0` 或负数：不能推送。
- 采集或同款状态未成功，即使 `newPrice` 有效：不能推送。
- Excel 输出包含 `newPrice` 列，且可推送/需处理数量与判定结果一致。
