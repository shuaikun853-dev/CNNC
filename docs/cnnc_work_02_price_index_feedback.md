# 中核商城价格指数勘误和运营反馈问题处理

> 适用频率：每日工作，原则上当天反馈当天处理。  
> 适用对象：中核商城或运营侧反馈的价格指数异常、指导价偏高/偏低、同款错绑、链接失效、供应商补充对标链接等问题。  
> 目标结果：核实反馈链接，修正SaaS同款绑定关系，重新计算价格指数，并将修正后的指数推送回中核商城。

## 1. 输入材料

运营反馈一般包含以下信息中的一项或多项：

| 信息 | 用途 |
|---|---|
| 标准商品编码 | 在中核商城标准商品价格库中定位商品 |
| 潜在标准商品编码 | 需要转换为SaaS监控商品编码后才能导入 |
| SaaS监控商品编码 | SaaS导入同款数据的核心编码 |
| 商品名称/供应商推品名称 | 辅助核验是否为同一商品 |
| 反馈原因 | 判断是价格高、价格低、同款错、链接失效还是缺同款 |
| 对标链接 | 作为新增/替换同款来源 |
| 反馈价格 | 与SaaS当前价格、页面实时价格、价格指数进行对比 |

## 2. 处理原则

1. **不能盲信反馈链接**：客户提供的链接通常可信，但仍要核对型号、规格、上架状态、页面价格。
2. **只修正有问题的同款**：原来SaaS采集的同款如果确实正确，不必全部解绑。
3. **错款必须解绑**：型号、规格、核心参数不一致时，解绑或驳回。
4. **高溢价谨慎保留**：高于参考价/当前指数约30%以上的链接，原则上不作为有效同款。
5. **低价优先**：在同款真实有效的前提下，倾向保留价格较低的数据，避免指导价过高。
6. **最终仍需满足两条不同商城同款**：否则不能生成有效价格指数。

## 3. 操作流程

### Step 1：接收并整理反馈

将运营反馈整理成一张处理表，建议字段如下：

| 字段 | 说明 |
|---|---|
| 反馈日期 | 便于日清追踪 |
| 标准商品编码 | 中核商城侧编码 |
| 潜在标准商品编码 | 如有则保留 |
| SaaS监控商品编码 | 转换后的导入编码 |
| 商品名称 | 监控商品名称/标准商品名称 |
| 反馈问题 | 价格异常、同款错误、缺同款、链接失效等 |
| 反馈链接 | 运营或商城提供的对标链接 |
| 页面价格 | 人工打开链接核对后的价格 |
| 处理结论 | 导入、解绑、保留、退回重新提供 |

### Step 2：编码转换

SaaS导入同款时使用的是SaaS监控商品编码，不能直接把中核商城的标准商品编码当作导入编码。

处理方法：

1. 使用“商城标识对应关系表”或最新编码关系表。
2. 用标准商品编码/潜在标准商品编码匹配SaaS监控商品编码。
3. 如果无法匹配到SaaS监控商品编码，先标记为“编码未匹配”，不要直接导入。
4. 只处理能定位到SaaS监控商品编码的数据。

### Step 3：查询当前价格指数和已绑定同款

1. 在中核商城标准商品价格库按标准商品编码查询。
2. 查看当前价格指数、状态、同款数量。
3. 在SaaS中按监控商品编码查询当前已绑定同款。
4. 记录当前同款商城、SKU、价格、链接、是否有效。

![中核商城标准商品价格库与接口信息](images/01_中核商城_标准商品价格库与接口信息.png)

### Step 4：核验反馈链接

逐条打开反馈链接，核验：

- 页面是否可访问。
- 商品是否上架。
- 品牌、型号、规格、关键参数是否与监控商品一致。
- 页面实时价格是否与反馈价格或导入价格一致。
- 商城是否与已有有效同款重复。

处理判断：

| 反馈链接情况 | 处理方式 |
|---|---|
| 同款、上架、价格合理 | 可导入或保留 |
| 同款但价格高于参考价约30%以上 | 一般不导入；必要时与运营确认 |
| 型号/规格不一致 | 退回或驳回，不导入 |
| 链接失效/下架 | 退回或驳回，不导入 |
| 与已有同商城重复 | 只保留一条更合理的链接 |

### Step 5：制作同款导入模板

使用以下模板之一：

- `同款导入模版-去一物多码.xlsx`
- `导入zhimport模版.xlsx`

核心字段按模板填写：

| 字段 | 填写要求 |
|---|---|
| 标品编码 | 部分模板可填0；按现有模板口径处理 |
| 标准商品编码 | 中核商城标准商品编码 |
| 商品名称/标品名称 | 监控商品名称或标准商品名称 |
| 单据id | SaaS监控商品编码/系统要求的商品ID，按模板口径填写 |
| 互联网标题 | 反馈链接页面标题或采集标题 |
| URL | 反馈链接 |
| SKUID | 链接中的SKU或平台商品ID |
| 供应商编码 | 平台/商城编码，如 jd 等 |
| 供应商名称/店铺名称 | 商城名称、店铺名称 |
| 价格 | 页面核验后的价格 |
| 评论数 | 页面评论数/销量，没有则填0或空值，按模板要求 |

> 注意：模板字段名称可能存在“带星号必填”和“不带星号”两个版本，以实际导入模板为准。带星号字段不能为空。

### Step 6：通过zhImport导入SaaS

1. 打开 `zhImport.html`。
2. 确认租户ID为 `188605`。
3. 确认商品池ID为 `222`。
4. 选择制作好的Excel文件。
5. 点击“导入数据”。
6. 查看响应码、响应描述、成功记录数和 success 标识。

导入成功后，在SaaS中重新查询该监控商品，确认同款已进入系统。

### Step 7：解绑错误旧同款

导入反馈链接后，需处理原有同款：

1. 打开同款明细。
2. 对比原有SaaS采集同款与反馈链接。
3. 错款、失效、价格异常高的旧同款执行解绑。
4. 正确且价格合理的旧同款可以保留。
5. 最终保证同一商城只保留一条有效同款。

### Step 8：重新计算并推送

1. 点击重新计算价格指数。
2. 查看计算后的价格指数是否符合预期。
3. 再次确认至少有2条不同商城有效同款。
4. 点击推送。
5. 回到中核商城确认状态和价格指数已更新。

## 4. 典型场景处理

| 场景 | 处理动作 |
|---|---|
| 运营反馈“价格太高” | 查看是否存在高价错款；解绑高价错款；补入低价有效同款；重算并推送 |
| 运营反馈“价格太低” | 检查是否绑定了非同款低价商品；错款解绑；保留真实同款价格 |
| 供应商提供两条新链接 | 核验后导入；如与旧同款冲突，解绑旧错款；重算推送 |
| 只有一条有效反馈链接 | 导入后仍不足两条，需要补采或退回继续提供；不能强推成功 |
| 反馈链接本身型号不一致 | 退回运营说明“非同款/型号不一致”，不导入 |
| 系统已有同款正确 | 不因反馈存在就全部替换，保留正确同款 |

## 5. 质量检查清单

- [ ] 已完成编码转换，使用的是SaaS监控商品编码。
- [ ] 反馈链接均已人工打开核验。
- [ ] 型号、规格、关键参数一致。
- [ ] 链接上架且价格可核对。
- [ ] 同一商城未重复保留多条。
- [ ] 高于参考价/价格指数约30%以上的异常高价已处理。
- [ ] 重新计算后价格指数合理。
- [ ] 已推送至中核商城并确认状态。
- [ ] 对无法处理的数据已记录原因并反馈运营。

## 6. 风险点

- **编码用错**：把标准商品编码直接当SaaS监控商品编码导入，会导致数据挂错商品。
- **旧错款未解绑**：即使导入了正确链接，旧错款仍会影响价格指数。
- **只看标题不看型号**：标题相似但型号后缀不同，仍可能不是同款。
- **页面价格未核对**：ES历史价格可能不是最新价格，页面价格与系统价格不一致会影响指数。
- **同商城重复**：同一商城多条同款会触发一物多码问题。
