# 运行环境与恢复：先读这页

> 当前是治理候选。通过审计不代表获准合并或上线；本轮不切生产、不替换数据库、不改计划任务。

详细操作只有一份权威说明：[安全发布与恢复](SAFE_RELEASE_AND_RECOVERY.md)。这里不再复制整套命令，避免两本说明书以后写出不同规则。

## 你需要知道的六件事

1. **代码与生产分开。** 开发候选可修改、测试；正在运行的目录不能直接施工。
2. **环境单独保护。** `.python-version` 与 `requirements.lock` 记录候选所用版本；不要把“建立了独立环境”理解成“生产已切换环境”。
3. **Git 一致不是全部一致。** 看板的 Git 对比与 `runtime_identity` 是两种证据；没有清单、没有启动证据或缺少计划任务核验时，不得显示完整匹配。
4. **备份不是整个目录复制。** SQLite 用 backup API；附件只收入已登记的业务证据名称。三个库、多个文件不保证来自同一瞬间。
5. **恢复只能去新目录。** 工具不会覆盖生产；C 盘及其别名、网络/设备路径、已有目录和冲突文件被拒绝。
6. **回退代码不会撤销业务。** 已创建的远端任务仍然存在，不能靠还原旧数据库让系统遗忘它们；恢复后必须对账。

## AI 去哪里查

| 要做什么 | 正确入口 |
|---|---|
| 备份、校验、恢复演练 | `tools/runtime_recovery.py` |
| 生成待审核运行清单、只读核验 | `tools/runtime_manifest.py` |
| 运行身份的实际判断 | `app/services/runtime_fingerprint.py` |
| 看板版本信息与错误降级 | `app/services/production_identity.py` |
| 新输出路径的共同安全规则 | `tools/local_output_paths.py` |

备份频率、保留周期、离机副本和业务允许的恢复时间仍需负责人明确；本轮不自动创建计划任务，也不把临时数据演练冒称真实灾备切换。
