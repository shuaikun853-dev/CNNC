## 三、问题与修复/优化明细

### P1 招商局提优"提交后复核"竞态误报(修复:证据规则放行)

- **现象**:任务创建、启用、提优 UPDATE 均成功(事务内复核通过并 commit,
  `affected_rows` 等于子任务数),但工具在 commit 后再读时部分行已被调度消费/状态变化,
  抛 `post-commit priority verification failed: exact target rows are not -1` 或
  `task_status changed during priority update`,按手册创建阶段整体中止,后续商城全部未建。
  08-24 下午命中 3 次:得力 1263583(89)、企事通 1263701(12)、浙江物产 1263730(34)。
- **根因**:提优工具的强校验与调度器消费子任务存在固有竞态;任务实际正常执行。
- **修复**:驱动层增加良性判定——错误文本命中四类提交后复核签名
  (`post-commit priority verification failed` / `task_status changed` / `is_valid changed` /
  `post-commit task_id verification mismatch`)**且** stdout 含 `affected_rows>0` 事务内证据时,
  记录 `PRIORITY_UNCONFIRMED_BENIGN` 事件后放行进入等待/导出,不再中止后续商城。
  其他任何失败仍立即停。
- **效果**:下午批次由 241/330 续跑到 309/330,未重复建任何任务。

### P2 提优 `no matching rows`(优化:带证据的容忍 + 事后补调)

- **现象**(08-24 晚批次):浙江物产 1266102、得力 1266116 任务创建启用成功,但提优的
  `s_task_info` 轮询 60 次均 0 行,`no matching rows for mall/task_number/create_time window`,
  创建阶段中止。
- **处理**:
  1. 容忍规则收紧:仅当 BATCH_STATE 已有该任务 `CREATED` 事件(任务确实建好)才记
     `PRIORITY_UNCONFIRMED_NOBOOST` 放行,等待/导出照常——**不盲放**;
  2. 事后补调:直接调用 `boost_zhaoshang_task_priority_after_create` 重跑提优。
- **效果**:得力 1266116 补调成功(`affected_rows=58`,全部 -1,记 `PRIORITY_UPDATED_RETRY`);
  浙江物产补调仍匹配不到,但其任务 15/15 正常执行并导出(提优只影响排队先后,不影响执行)。

  输出文件名追加 `_史泰博阶段` 后缀,避免把半成品误当完成品;BATCH_STATE 记录阻塞原因。
  15:46-15:53 按用户要求直连重试 10 次仍不通,按"找不到就置空"先定稿 75/330;
